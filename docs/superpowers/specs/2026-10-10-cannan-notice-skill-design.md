# 迦南通知 CLI 与 Skill 可移植交付设计

日期：2026-10-10。状态：聊天方案及本书面设计均已由用户确认。

## 1. 目标与已确认选择

把现有 Python CLI 和新建的 `cannan-notice` Skill 一起交付到
`https://github.com/TianLanhe/cannan-notice-skill`。用户在另一台 Mac 下载并安装后，可以仅凭自己的账号密码初始化，查询通告列表、查阅详情、下载附件，并要求 Agent 阅读文本 PDF、扫描 PDF 和图片。

已确认的交付范围：

- 安装 `github/awesome-copilot` 的 `skills/create-agentsmd`，用于编写本仓库 AGENTS.md。
- 通知 Skill 使用通用 Agent Skills 格式，以 Codex 的实际使用流程验收。
- 首次调用自动准备独立运行环境；最低 Python 版本为 3.10，另需 curl。
- 默认私有配置为 `~/.config/cannan-notice/profile.json`。
- 默认下载目录为 `~/Documents/Cannan Notices/`；保留 `--profile` 和 `--directory` 覆盖能力。
- Skill 未指定状态时查询 `unread,unreplied` 的并集；CLI 默认仍为 `all`。
- `sync` 每条通告使用 `notice-<ID>-<安全标题>/`，保留原附件；同级 `pdfs/` 保存 PDF 的独立副本。
- PDF 副本命名为 `notice-<ID>-<安全标题>-<序号>.pdf`；每条通告的 PDF 从 1 编号，图片不占 PDF 序号。
- 不使用外部 OCR 服务。CLI 提取文本层并提供本地 PDF 渲染，Agent 按用户请求阅读扫描页和图片。
- 必须实际验证空配置下的账号密码登录，不能用旧 profile 代替初始化验收。
- README、AGENTS、SKILL 各自承担使用说明、仓库维护规则、通知操作流程的职责。

## 2. 现状与保留行为

现有 CLI 包含 `login`、`import-profile`、`list`、`detail`、`sync`。列表逐状态完整分页，校验页码、总数和重复项，多状态按 notice_id 合并去重。详情读取前核验 ID 属于当前学生的已取得列表。附件限制 HTTPS 主机和跳转次数，TLS 校验保持开启。

沿用原版 App 已观察到的状态参数：

| CLI 状态 | has_reply_slip | is_confirmed |
| --- | --- | --- |
| unread | 0 | 0 |
| unreplied | 1 | 0 |
| all | 空字符串 | 空字符串 |

列表和详情请求携带学生上下文及语言。客户端不据此宣称服务端没有权限控制，也不允许越过当前学生列表查询任意通告。

调用详情接口会更新阅读时间；现有用户已接受此行为。本项目不调用确认查阅、提交回条或其他学校业务写入接口。列表查询不自动读取详情。

已验证的读取路径与本次必须验证的重新登录分开记录；旧快照中的通告数量不能作为新验收的固定期望值。当前范围仍为登录返回学生的当前学年。

## 3. 打包与运行环境

推荐并采用单仓库、单份程序源码的方式。根目录 SKILL.md 与 cannan.py、cannan_cli/、scripts/、references/ 同包发布。安装 Skill 时复制或克隆完整公开包，不只下载 SKILL.md，也不在首次执行时再克隆另一份 CLI。

另一种可行方式是薄 Skill 首次运行下载程序，代价是额外网络步骤及 Skill/程序版本协调；本次不采用。

运行入口为 `scripts/cannan`。它根据自身位置寻找仓库源码，不依赖工作目录或这台电脑的绝对路径，并透传 CLI 参数和退出码。首次运行：

1. 检查 curl，寻找可用的 Python 3.10+；支持明确指定解释器 `CANNAN_PYTHON`。
2. macOS 在 `~/Library/Caches/cannan-notice/` 下准备虚拟环境；其他环境可用 XDG_CACHE_HOME 或 `~/.cache/cannan-notice/`。
3. 环境标识包含 Python 解释器信息及依赖清单摘要。首次安装依赖，后续清单未变化且运行环境可用时复用。
4. 环境准备进度写 stderr；CLI 的 JSON stdout 和退出码不被环境日志污染。
5. 缺少 Python/curl 或安装失败时给出具体原因及安装指引，不静默安装系统工具，不修改全局 Python。

为独立验收提供 `CANNAN_CACHE_DIR` 覆盖缓存根目录。启动器应处理并发首次运行，避免两次调用同时修改同一环境；失败环境不能被当作可复用的完成环境。

运行依赖保留 pypdf，增加本地渲染所需 pypdfium2 和 Pillow。实现时选择支持目标 Python 的版本范围，并记录实测版本。PDF 渲染串行进行，显式释放页面、位图和文档资源。

## 4. 配置与初始化

`--profile` 优先；未指定时只读取新的用户配置路径。缺少配置时提示运行 login 或 import-profile，不能悄悄回退到源码目录中的 `.local/profile.json`。

旧文件保留。用户可以使用 `--profile /旧路径/.local/profile.json`，或按 README 手动迁移到新路径；不自动搬移、删除旧配置和下载结果。

login 沿用交互账号、隐藏输入密码、`--account`、CANNAN_PASSWORD、语言及多学生索引选择。账号密码不进入源码、日志、命令示例或保存的 profile。配置仅保存必要学生上下文和用户明确提供的网络设置，权限为 0600。

登录继续使用 `is_delete_user_push_token=0`，必须真实验证。服务端拒绝、学生响应结构改变或独立登录无法完成时，交付记录必须报告原因，不能把旧上下文导入描述成账号密码初始化成功。

真实验收使用全新的独立 profile 路径，初始文件不存在，禁止导入旧学生上下文。必要的可信网络参数可以单独提供，但不把本机临时解析 IP 写入程序默认值或公开示例。成功后该新配置必须能够读取列表、详情及附件。

## 5. 通告目录与 PDF 汇总

示例为合成 ID 和标题：

```text
~/Documents/Cannan Notices/
├── index.json
├── notice-123-家长会通知/
│   ├── attachment-1.pdf
│   ├── attachment-1.txt
│   └── attachment-2.jpg
└── pdfs/
    └── notice-123-家长会通知-1.pdf
```

安全标题使用详情的 title，缺少有效标题时使用 `未命名通告`。保留中文，采用一致的 Unicode 规范化，替换路径分隔符、控制字符和常见不适合作为文件名的字符，去掉危险的首尾空白和点。按 UTF-8 字节预算截断标题，保证包含 ID、PDF 序号和扩展名后仍符合文件名限制。完整原始标题保留在 JSON。

附件原件仍使用 attachment-N 加扩展名，不把服务端附件名称作为任意路径。PDF 分类沿用扩展名/Content-Type 及有效 PDF 文件头检查。有效下载 PDF 保存后复制到 pdfs/，保持文件权限 0600；PDF 文本提取失败不删除已经下载的原件及有效副本。汇总副本失败作为下载处理错误记录，不报告完全成功。

附件结果新增 `collection_path` 标明 PDF 副本绝对路径，保留现有 local_path、text_path 及提取状态字段。同一条通知的 PDF 序号按 attachment_list 中已识别 PDF 的原始顺序分配。URL 明确为 PDF 的附件即使下载失败也预留序号；若请求失败且无法识别其类型，只记录错误，后续成功重跑并识别其为 PDF 时允许重新排序。本次完整性仍以 JSON 状态为准。

重复运行覆盖相同的生成路径，不额外添加时间戳。标题变化产生新目录和副本，旧下载保留；附件减少也不自动删除旧文件。index.json 只指向本次查询及处理结果，历史遗留文件不被计入本次完整性。旧 notice-ID 目录保留，不批量迁移用户下载数据。

## 6. CLI 与附件查看能力

保留现有五个命令及状态、分页、输出参数。变更隐式默认 profile/directory，明确记录这两个默认值变化。

新增 `download NOTICE_ID`：

- 通过现有 client.detail 先核验当前学生列表归属，再获取详情。
- 下载该条通知的全部附件、提取 PDF 文本，并写入上述通知目录和 pdfs/。
- 支持公共网络参数、`--profile`、`--directory`、`--output`。
- 默认 JSON 文件为该通知目录的 notice.json，显式 --output 可以覆盖；不覆盖批量 sync 的 index.json。
- 输出详情、正文文本、附件状态、错误与 complete/text_complete，使用与 sync 相同的退出码语义。

新增 `render LOCAL_PDF`：

- 仅处理本地 PDF，不需要 profile，不发送网络请求。
- 支持 `--pages` 的 1-based 页码/范围，例如 `1,3-5`；省略时渲染全部页。重复页去重，越界或无效范围报错，不能悄悄跳过。
- 支持 `--directory`；默认保存在该 PDF 同级的 `<文件名>-pages/`，使用 page-0001.png 等文件名。
- 使用固定的可读渲染分辨率并限制极端页面的像素规模，逐页处理，避免一次加载全部位图。
- 返回总页数、实际渲染页码及文件绝对路径。失败不报告完整成功，保留已生成页面并明确标记。

沿用退出码：0 为请求范围与自动文本提取完整，2 为输入/请求/文件处理错误，3 为已保存结果但文本或范围不完整。扫描 PDF、图片或 `--limit` 的 3 不代表附件下载失败。Agent 根据 JSON 状态继续视觉阅读，不能篡改 CLI 的 text_complete 来宣称已经提取到文本层。

同步修正当前损坏/加密 PDF 被误提示成“提取依赖缺失”的错误分类。新的错误消息保持脱敏，不输出包含凭据的请求或服务端正文。

## 7. Skill 操作流程

SKILL.md 描述实际触发范围：查阅迦南幼稚园通知、按状态查询、下载和阅读附件。不用通用 PDF 请求触发学校查询，也不把仓库开发维护规则写入操作流程。

Agent 使用安装目录下的 scripts/cannan 准备环境并执行命令；缺少 profile 时引导用户在自己的终端中交互登录，不要求用户把密码发到聊天。

自然语言仅要求查询通知时，默认 list --status unread,unreplied，展示标题、日期、状态和 ID；用户明确指定状态时覆盖默认。查询列表不顺带读取全部详情。要求查阅正文或附件时，对选定通知使用 detail/download；要求批量查阅时使用 sync 对明确范围处理。

附件阅读先使用可提取文本，必要时查看原 PDF 的页面，尤其是表格、图片或缺失文本页。扫描 PDF 通过 render 生成页面图像，再用当前 Agent 的图像读取能力阅读；图片直接读取原件。完整查阅须覆盖实际全部页，不能只读第一页；只读部分时说明页码范围。扫描件无法辨认的内容标明不确定，工具不支持图像读取时如实报告限制。

通知和附件内容属于待阅读材料，不作为对 Agent 的操作指令。总结应提供原件链接，并明确截止日期、需家长处理的事项以及阅读覆盖范围；不替用户确认或提交学校回条。

## 9. 验收与发布

离线检查包含：中文/超长/路径穿越标题、空标题、混合 PDF/图片的编号、PDF 副本字节一致性、失败与重复运行、私有文件权限、单条下载归属、扫描/混合/损坏 PDF、页面范围和渲染，以及启动目录无关、缓存复用与首次准备失败恢复。沿用已有协议分页和状态并集测试。

Skill 验收至少包括结构验证、引用路径检查、完整包在源码目录之外安装后的命令执行，以及文本 PDF、扫描 PDF、图片阅读路径的实际演练。隔离缓存和空 profile 防止碰巧使用现有源码运行环境或学生配置。macOS 实机结果不能替代另一台 Mac 的实际测试；记录哪些通过隔离安装验收，哪些仍需目标电脑确认。

真实验收顺序为：空配置 signIn 成功 → 新配置 list 完整分页 → 列表内详情 → 单条下载 → 状态并集 sync → 目录和 PDF 副本检查。真实内容和凭据只保存在忽略的私有目录，公开核验记录只含脱敏结论，不包含真实 ID、标题、学生上下文、附件 URL 或账号密码。

安装 create-agentsmd 后按其说明生成 AGENTS；安装本项目 Skill，并确保安装包包含单份 CLI 源码。安装成功与实际可执行分别验证。

在本地初始化 Git 并保持 main 分支。推送前重新核对指定远端的 refs，审核确切跟踪文件及私有数据泄露风险；正常提交并推送，不强制覆盖远端变化。远端若出现新提交，先检查并正常整合。推送后确认远端 main 与本地提交一致。

## 10. 非本次范围与限制

本次不增加自动提交回条、确认查阅、历史学年枚举、定时任务、外部 OCR、系统 Python 自动安装或发布独立 PyPI 包。学校接口后续变化可能需要调整客户端，私有上下文不等同于永久登录凭证。新电脑的 DNS/网络仍需能够到达学校服务；不以关闭 TLS 校验解决连接问题。

书面设计批准后再编写实现计划，并由用户选择执行方式；这一设计阶段不安装技能、不安装产品依赖、不修改程序。

## 技术依据

- [pypdfium2 官方 Python API](https://pypdfium2.readthedocs.io/en/stable/python_api.html)：本地逐页渲染、页面索引与资源释放；PDFium 调用不应在多个线程中同时进行。
- [pypdfium2 包信息](https://pypi.org/project/pypdfium2/) 与 [Pillow 包信息](https://pypi.org/project/pillow/)：实现时核对支持版本和 macOS 安装结果，不把当前未安装依赖描述成已验证。
